# المسرد: الكلمات الصعبة

جدول سريع للمصطلحات التي قد تسمعها في نسّاج، مع شرح كل مصطلح بجملة واضحة.

## المصطلحات (A–Z)

| المصطلح | الشرح |
|---|---|
| **المنسّق** | الذكاء الذي يستقبل طلبك ويوزّعه على الوكلاء — مثل مدير المشروع. |
| **الوكيل** | خبير واحد متخصص: مبرمج، مصمم، محلل. يفعل الشغل الفعلي. |
| **جلسة** | محادثة مستمرة واحدة حول مهمة — قد تستمر دقائق أو ساعات. |
| **مشروع** | مجلد عمل كامل: ملفات، كود، تاريخ، ومهام. مثل nassaj-dev. |
| **لوحة المشروع** | جدول حي يلخص حالة المشروع: المراحل، المهام، الحالات. |
| **المرحلة** | قسم كبير من المشروع (مثل: التصميم، الترميز، الإطلاق). |
| **السبرنت** | دفعة عمل قصيرة (أسبوع تقريباً) لإنجاز مجموعة مهام محددة. |
| **المهمة** | عمل محدد قابل للإنجاز (مثل: «برمج زر الدفع»). |
| **ADR** | قرار معماري موثّق عن بنية المشروع (مثل: اختيار React). |
| **حصة الاستخدام** | ميزانية الساعات: كل موظف عنده 5 ساعات بالجلسة + ساعات أسبوعية. |
| **نافذة السياق** | مساحة الذاكرة التي يحتفظ بها نسّاج من الجلسة (إذا امتلأت توقّف). |
| **الالتزام البرمجي (`commit`)** | تسجيل تغيير في الكود مع رسالة توثّق ما تغيّر. |
| **البناء (`build`)** | عملية تجهيز الكود وتحويله إلى تطبيق قابل للتشغيل. |
| **إعادة التشغيل (`restart`)** | إيقاف الخادم أو التطبيق ثم تشغيله من جديد. |
| **النشر (`deploy`)** | إيصال نسخة التطبيق إلى البيئة الفعلية (الإنتاج). |
| **الخلفية (`backend`)** | الجزء غير المرئي للمستخدم: الخوادم وقواعد البيانات ومنطق العمليات. |
| **الواجهة (`frontend`)** | الجزء الظاهر للمستخدم: الصفحات والأزرار والألوان. |
| **واجهة برمجة التطبيقات (`API`)** | قناة منظّمة تتواصل من خلالها الواجهة مع الخلفية. |
| **قاعدة البيانات** | خزانة ضخمة تحفظ كل البيانات (مستخدمين، مبيعات، إلخ). |
| **RTL** | اليمين لليسار — طريقة عرض الواجهة بالعربية (اليمين أولاً). |
| **UI** | واجهة المستخدم — كل ما ترى: أزرار، نصوص، صور. |
| **UX** | تجربة المستخدم — كيف تشعر عند استخدام الموقع. |
| **تصميم** | رسم الموقع قبل البرمجة: الألوان، التخطيط، الشكل. |
| **برمجة** | كتابة الكود الفعلي بلغات مثل JavaScript أو Python. |
| **اختبار** | فحص الموقع للتأكد من أنه يشتغل بلا أخطاء. |
| **خطأ (`bug`)** | سلوك لا يعمل على النحو المتوقع. |
| **إصلاح** | تصحيح الخطأ. |
| **نسّاج** | أداة تطوير بالذكاء الاصطناعي يشغّلها فريقك على خادمه (نسّاج ديف تحديداً: fork من claudecodeui برخصة AGPL-3.0). |
| **نسّاج كور** | العقل: المنسّق والوكلاء والقواعد التنظيمية — محتوى حوكمة يضبطه كل فريق لنفسه، ولا يُشحن مع التطبيق. |
| **نسّاج ديف** | الواجهة: الموقع الذي تفتحه بالمتصفح على عنوان نسّاج في مؤسستك. |
| **Claude** | نموذج ذكاء اصطناعي متقدم من شركة Anthropic — هو محرّك تنفيذ الوكلاء الرئيسي وينفّذ معظم المهام البرمجية والتصميمية. |
| **agy / Antigravity** | مزوّد بديل داخلي (أداة تشغيل بديلة من نسّاج) — يمكن استخدام agy بدل Claude في مهام معينة إذا كان أنسب. |
| **Fable 5** | أعلى نموذج Claude متاح حالياً (عاد للمنصة 2026-07-02) — يُستخدم كأرضية للقرارات المعمارية والعمل الحسّاس. ليس اسماً ثابتاً: لو غاب، تهبط الأرضية تلقائياً لأعلى نموذج تالٍ (اليوم: Opus 4.8). |
| **Sonnet 5** | مستوى متوسط من نموذج Claude — توازن بين القوة والسرعة، يستخدم في برمجة الواجهات والبحث العلمي. |
| **Haiku 4.5** | أخف مستويات نموذج Claude — سريع وخفيف، يستخدم في توثيق وكتابة محتوى بسيط. |
| **منتقي مستوى الجهد** | قائمة منسدلة في صندوق الكتابة تضبط عمق تفكير الوكيل في الجلسة التفاعلية: auto / low / medium / high / ultracode. |
| **مزوّد الجلسة** | خيار يحدد أي محرك يشغّل محادثتك: Claude أو agy — يؤثر على السرعة والقدرات. |
| **هوية بصرية** | الألوان والخطوط والشعار الموحّد للشركة. |
| **branded house** | نمط تصميم واحد موحّد لكل المنتجات والخدمات — علامة واحدة جامعة على كل شيء. |
| **token** | وحدة تقاس بها تكاليف استخدام الوكلاء (مثل كلمات مكتوبة). |
| **الذاكرة المؤقتة (`cache`)** | مساحة سريعة تحفظ نسخة من البيانات كثيرة الاستخدام لتجنّب حسابها من جديد كل مرة. |
| **جلسة (`session`)** | جلسة عمل؛ وهي المصطلح المعرّف أعلاه نفسه. |
| **المستخدم (`user`)** | أي شخص يستخدم نسّاج، مثل أعضاء فريقك. |
| **أفاتار** | صورة صغيرة تمثلك بجانب اسمك. |
| **شارة** | علامة صغيرة بجانب الاسم توضح الدور (مثل: مالك، محرر). |
| **أرشفة** | إخفاء شيء عن القائمة الرئيسية، لكن يبقى موجود للبحث. |
| **تحديث حي** | الموقع يتحدّث تلقائياً بلا تحديث يدوي. |
| **WebSocket** | تقنية تسمح للموقع بإرسال بيانات جديدة فوراً. |
| **قراءة فقط** | إذن محدود يتيح لك القراءة من دون التعديل. |
| **صلاحية** | الإذن الذي يحدد ماذا تستطيع تعمل في الموقع. |
| **تشفير** | تحويل البيانات لصيغة غير مفهومة حماية من الهاكرز. |
| **كلمة المرور** | رمز سري يثبت هويتك (تشفّر قبل ما تُحفظ). |
| **ثيم** | نمط ألوان كامل (فاتح، داكن، الكِندِي). |
| **التوجيه (`prompt`)** | النص الذي تكتبه للوكيل لتطلب منه تنفيذ مهمة معينة. |
| **placeholder** | صورة أو مكان فارغ تحت الإنشاء (قيد التحضير). |
| **قالب** | نموذج جاهز تستطيع تنسخه وتعدّله. |
| **توثيق** | كتابة شرح عن الكود أو الميزة. |
| **رسالة الالتزام (`commit message`)** | الرسالة المصاحبة للتغيير، وتوضّح ما عُدّل. |
| **git** | نظام تتبع الكود — يحفظ كل تغيير وتاريخه. |
| **GitHub** | الموقع الذي يحفظ فيه الكود (مثل Google Drive لكن للبرمجة). |
| **اختبار آلي** | برنامج يختبر الكود تلقائياً بلا تدخل يدوي. |
| **جودة** | مستوى نظافة الكود والأداء والأمان. |
| **الأداء (`performance`)** | سرعة تحميل الموقع وتنفيذه للعمليات. |
| **أمان** | حماية البيانات من المخترقين والأخطاء. |
| **CRUD** | أربع عمليات أساسية: الإنشاء (`Create`)، والقراءة (`Read`)، والتحديث (`Update`)، والحذف (`Delete`). |
| **نقطة النهاية (`endpoint`)** | عنوان محدد في الخادم يستقبل الطلبات، مثل عنوان يعيد قائمة مشاريعك. |
| **الطلب والاستجابة (`request/response`)** | الطلب الذي يرسله الموقع والاستجابة التي يعيدها الخادم؛ فمثلاً تطلب الواجهة حالة المهام عند فتح لوحة المشروع. |
| **استدعاء** | طلب رسمي من المنسّق للوكيل: "افعل هذا من فضلك". |
| **تفويض** | إعطاء شخص إذن بفعل شيء (مثل: فوّضت الوكيل بالبرمجة). |
| **موافقة** | قبول رسمي من المالك أو صاحب السلطة. |
| **قرار** | اختيار رسمي بين بدائل متعددة (مثل: قررنا استخدام React). |
| **سياسة** | قاعدة موثّقة يجب اتباعها (مثل: كل كود جديد يحتاج اختبار). |
| **استراتيجية** | خطة طويلة الأمد توضح الاتجاه (مثل: نركز على السوق الخليجية). |
| **ميزة** | شيء جديد نضيفه للموقع. |
| **تحسين** | جعل شيء موجود أفضل وأسرع. |
| **تصحيح** | إصلاح خطأ أو مشكلة. |

## مثال عملي: أين يقع نسّاج من عملك؟

```
مؤسستك
  └─ منتجاتك — ما تبنيه وتبيعه لعملائك
  └─ نسّاج — أداة داخلية يستخدمها فريقك لبناء تلك المنتجات
```

**بكلمات بسيطة:** نسّاج ليس منتجاً تبيعه لعملائك — هو ورشة العمل التي تُبنى فيها منتجاتك. حين يُضاف زرّ جديد إلى أحد منتجاتك، الوكيل الذي يبرمجه يعمل داخل نسّاج، والزرّ ينتهي في مستودع منتجك.

---

إذا بقي لديك مصطلح غير موجود، فاسأل عنه في محادثتك؛ وسيجيبك المنسّق والوكلاء.
