# تجهيز التحديث المحلي / Local update preparation

`oid-update-candidate.mjs` جزء التحضير في ADR-160. يستدعيه المستهلك لطلب مالك محفوظ في حالة `preparing`، ويعيد هدفًا من نوع `nassaj-oid-triple-target/v2`. لا ينشئ موافقة ولا يروّج ملفات حية ولا يعيد تشغيل الخدمة.

يقرأ المصدر من OID الكامل الحالي لـ`main`، ويقارن ملفات snapshot والنسخة الخاصة بـGit blob inventory قبل التثبيت وبعده وبعد البناء، ويرفض الملفات والأدلة غير الموجودة في inventory؛ الاستثناء الوحيد هو `node_modules` الجذري أثناء مرحلتي ما بعد التثبيت والبناء. تعمل `npm ci` وأدوات بناء العميل والخادم من الاعتماديات المرحلية في `oid-builds/<oid>/<nonce>/source`؛ لا تتغير HEAD أو index أو تعديلات المستخدم. تُحفظ الأجيال ضمن مخازن المرشحين القائمة، والاعتماديات في `dependency-candidates/<sha256>` مع دليل مستقل بوضع `0600` في `dependency-evidence/<dependencyContractSha256>.json` لا يُستبدل بعد إنشائه. تُحذف نسخة العمل الخاصة بعد نجاح التخزين؛ محاولة فاشلة تبقى للفحص.

البصمة الجديدة مستقلة عن v1 وتشمل المحتوى والأوضاع والأدلة الفارغة والروابط الداخلية النسبية. جذر جيل الاعتماديات مملوك لمستخدم الخدمة وبوضع `0700` حصريًا للسماح بالتبادل بين الأدلة؛ محتوياته للقراءة فقط. يعاد فحص البصمة قبل النقل وبعده، وتُرفض الروابط المطلقة أو الهاربة أو المعطوبة والملفات الخاصة وhardlinks. يسبق إيصال الاستعداد اختبار native المعزول من الكبسولة، دون استيراد التطبيق أو إتاحة بيانات المستخدم.

سياسة local V2 تتطلب حاليًا npm `11.16+` أو `12+`، وتفحص الخيارات الفعلية والموافقات الدقيقة في `package.json#allowScripts` مقابل الحزم ذات install scripts في lockfile على المنصة الحالية. تُرفض الموافقات العامة وتعارضات إعدادات scripts. هذا الشرط خاص بالتحضير المحلي الجديد؛ `source-update-candidate.mjs` يحتفظ بمسار الإصدار والتحقق من سلطته السابقين ولا يضيف شرط نسخة npm إلى عقد الإصدارات. موافقات حزم المشروع السبع مخصصة لـLinux؛ حزم fsevents المقيدة بـDarwin مستثناة من جرد Linux.

إثبات الهوية لا يمنح إذن تفعيل حي: يشير `oidTripleAdmissionV2` إلى دعم المنفذ الثلاثي بعد قبول شيفرته، ويظل ترويج المرشح حيًا محجوبًا حتى قبول اختبار الأثر الفعلي ومصفوفة التعافي. عقدة الإصدار تستمر باستعمال بوابة المصدر القائمة، ولا يُصنع release plan مزيف لتجهيز OID محلي.

The adapter prepares three generations for an existing owner request. It copies immutable Git blob content into private disk-backed scratch, installs there, loads each target's builder with staged dependencies, then seals and probes dependencies before publishing a typed candidate descriptor. It does not activate runtime. Canonical dependency roots use service-owned mode `0700` for cross-parent atomic exchange; descendants remain read-only and their relocation-stable identity is rechecked. The existing source-release plan validator and release npm compatibility remain unchanged. Local V2 currently requires npm 11.16 or later and exact release-owned lifecycle approvals. The capability flag identifies reviewed protocol support; live promotion remains gated on the real-artifact acceptance and recovery matrix.
